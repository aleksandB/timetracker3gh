## ❌ Критические архитектурные проблемы

### 1. **timeEntrySlice не разделяет записи по пользователям (КРИТИЧНО)**

**Проблема:**
- Все записи времени хранятся в одном массиве без разделения по пользователям
- `useTimeTrackingData` берет все entries без фильтрации по `currentUser.id`
- Разные пользователи видят чужие записи

**Пример:**
```typescript
// ❌ Плохо - берет ВСЕ записи
const entries = useSelector((state: RootState) => state.timeEntries);

// ✅ Должно быть - фильтровать по currentUser.id
const entries = useSelector(selectTimeEntriesByUserId(currentUser.id));
```

**Файлы:**
- `src/lib/hooks/useTimeTrackingData.ts`
- `src/store/slices/timeEntrySlice.ts`
- `src/components/features/TimeTracker/index.tsx`

### 6. **Типизация (21 проблема с `any`)**

**Проблемы:**
- Использование `any` в 21 месте вместо правильных типов
- TODO комментарии вместо реализации типов
- Слабая типизация в хуках и компонентах

**Примеры:**
```typescript
// ❌ Плохо
currentProject: any | null; // TODO: Заменить any на ProjectType
setCurrentProject: (project: any | null) => void;

// ✅ Должно быть
currentProject: Project | null;
setCurrentProject: (project: Project | null) => void;
```

**Файлы с проблемами:**

### 2. **Неправильное использование Redux**

**Проблемы:**
- Использование обычных функций вместо `createAsyncThunk`
- Прямая работа с DOM в Redux (saveData)
- Нет типизации для thunks
- Смешение синхронных и асинхронных операций

**Пример:**
```typescript
// ❌ Плохо
export const loadData = (jsonData: InitialData) => (dispatch: any) => {
  dispatch(loadDataStart());
  // ...
};

// ✅ Должно быть
export const loadData = createAsyncThunk(
  'init/loadData',
  async (jsonData: InitialData, { dispatch }) => {
    // ...
  }
);
```

**Файлы:**
- `src/store/slices/initSlice.ts` (строки 70, 95)

### 4. **Нет нормализации данных в Redux**

**Проблемы:**
- Данные хранятся в виде массивов
- Нет нормализации (entities + ids)
- Сложные селекторы для поиска связанных данных
- Потенциальные проблемы с производительностью

**Пример:**
```typescript
// ❌ Текущая структура
state.projects.projects: Project[]
state.projects.directions: Direction[]

// ✅ Нормализованная структура
state.projects.entities: { [id: string]: Project }
state.projects.ids: string[]
state.directions.entities: { [id: string]: Direction }
state.directions.ids: string[]
```

### 6. **Обработка ошибок**

**Проблемы:**
- Использование `alert()` для ошибок
- `console.error` без обработки
- Нет централизованной обработки ошибок
- Нет пользовательских уведомлений

**Примеры:**
```typescript
// ❌ Плохо
alert("Ошибка при чтении файла JSON.");
console.error("Ошибка при загрузке данных:", error);

// ✅ Должно быть
toast.error("Ошибка при чтении файла JSON.");
// + централизованная обработка ошибок
```

### 7. **Дублирование кода**

**Проблемы:**
- Похожая логика в разных хуках

## 🎯 Почему рефакторинг, а не переписывание?

### ✅ Преимущества рефакторинга:

1. **Проект работает** - не нужно ломать работающий функционал
2. **Базовая структура есть** - можно улучшить, а не создавать заново
3. **Меньше рисков** - постепенные изменения безопаснее
4. **Можно делать инкрементально** - можно внедрять по частям
5. **Быстрее** - 2-3 недели vs 1-2 месяца переписывания

### ❌ Почему не переписывание:

1. **Проект не настолько плох** - есть хорошая база
2. **Переписывание рискованно** - можно потерять функционал
3. **Дольше** - нужно будет переписать все с нуля
4. **Нет гарантий** - новые баги, потеря времени
