# Новая архитектура проекта: Иерархические проекты и типы

## Обзор

В рамках фазы 1 рефакторинга была реализована новая архитектура для управления проектами и направлениями. Основные изменения включают:

1. Введение иерархической системы типов (Types)
2. Перевод проектов на древовидную структуру
3. Разделение связей проектов и направлений
4. Улучшение системы управления проектами

## Структура данных

### Type (Тип)
```typescript
interface Type {
  id: number;           // Уникальный идентификатор
  name: string;         // Название типа
  parentId: number | null; // ID родительского типа (null для корневых типов)
}
```

**Особенности:**
- ID 1-100: зарезервированы для корневых типов (доступны для проектов с parentId: null)
- ID > 100: для подтипов (доступны для подпроектов с parentId: non-null)

### Project (Проект)
```typescript
interface Project {
  id: string;           // Уникальный идентификатор
  parentId: string | null; // ID родительского проекта (null для корневых проектов)
  name: string;         // Название проекта
  typeId: number;       // Ссылка на Type.id
  shortName?: string;   // Краткое обозначение (опционально)
}
```

**Особенности:**
- Поддержка древовидной структуры через parentId
- Связь с типом через typeId
- Поддержка иерархии: корневые проекты (parentId: null) и подпроекты (parentId: non-null)

### Direction (Направление)
```typescript
interface Direction {
  id: string;           // Уникальный идентификатор
  projectId: string;    // ID проекта, к которому привязано направление
  name: string;         // Название направления
  color: string;        // Цвет для визуализации
  type: DirectionType;  // Тип направления (administrative | technical)
  isSpecial?: boolean;  // Специальное направление (отпуск, больничный и т.п.)
}
```

**Особенности:**
- Привязка к проекту через projectId
- Может быть использовано в разных проектах (одинаковое направление в разных проектах)

### TimeEntry (Запись времени)
```typescript
interface TimeEntry {
  id: string;           // Уникальный идентификатор
  userId: string;       // ID пользователя
  directionId: string;  // ID направления
  projectId: string;    // ID проекта (новое поле)
  date: string;         // Дата в формате YYYY-MM-DD
  regular: number;      // Обычные часы
  overtime: number;     // Сверхурочные часы
  description?: string; // Описание (опционально)
}
```

**Особенности:**
- Добавлено поле projectId для связи с проектом
- Теперь направление может быть использовано в разных проектах

### User (Пользователь)
```typescript
interface User {
  id: string;           // Уникальный идентификатор
  name: string;         // Имя пользователя
  role: UserRole;       // Роль (admin, manager, employee)
  position: string;     // Должность
  projectIds: string[]; // Список проектов, доступных пользователю (новое поле)
}
```

**Особенности:**
- Добавлено поле projectIds для управления доступом к проектам

## Преимущества новой архитектуры

### 1. Гибкость связей
- Одно и то же направление может быть использовано в разных проектах
- Поддержка сложных иерархий проектов
- Возможность создания подпроектов с разными типами

### 2. Иерархическая структура
- Поддержка древовидной структуры проектов
- Легкое добавление новых уровней иерархии
- Четкая организация проектов по типам

### 3. Улучшенное управление
- Разделение управления проектами и направлениями
- Поддержка древовидного выбора проектов в интерфейсе
- Улучшенная фильтрация и отображение данных

## Миграция данных

При миграции с предыдущей структуры:
1. Создаются типы по умолчанию (Административный, Технический и т.д.)
2. Проекты преобразуются с привязкой к соответствующим типам
3. Направления остаются без изменений
4. Записи времени обновляются с добавлением projectId

- Отображение иерархии проектов

## Примеры использования

### Создание иерархии проектов
```
Основной проект (typeId: 2)
├── Подпроект 1 (typeId: 2)
│   ├── Frontend разработка (typeId: 102)
│   └── Backend разработка (typeId: 103)
└── Подпроект 2 (typeId: 2)
```

### Использование направлений
- Направление "Разработка" может использоваться в разных проектах
- Направление "Встречи" может быть добавлено к любому проекту
- Специальные направления (отпуск, больничный) остаются в административных проектах
